## Назначение

Host-neutral `assessPhrase(const Phrase&, const PhraseMatchRequest&)` проверяет
фразу против уже рассчитанного материала каждого гармонического участка.
Сначала гармоническое соответствие, затем независимый пользовательский tension.
Сам поиск, библиотека, ранжирование и редактор фраз остаются последующим этапам.

0.4e не добавляет музыкальные источники и не назначает уровни автоматически.
В интерфейсе доступно прежнее поведение 0.4d; изменяется подпись версии.
Контракт проверяется автоматическими тестами до появления фразовой библиотеки.

## Входные данные

- `PhraseMatchRequest.slots`: готовые `ImprovisationResult` и начало/конец участков
  в относительных beats. Анализ аккорда/оборота повторно не запускается.
- `requestedTension`: optional T1/T2/T3; отсутствие запроса — «Все». Адаптер
  `requestedPhraseTension` переводит сохранённый UI-фильтр 0/1/2/3.
- `Phrase.tensionClassified`: явный факт назначения описательного уровня самой
  фразе. Существующий enum по умолчанию T1 без этого флага не считается оценкой.
- `harmonicRequirements`: ограничения конкретных участков — реальное качество
  аккорда, существующий source rule, его версия/относительный корень, локальный
  оборот и major/minor цель, при необходимости подтверждённая.
- `Phrase.harmonicPattern`: при заданном значении требуется наличие этого оборота
  в используемом анализе; строгие ограничения конкретного участка задаются через
  его requirement. Matcher не распознаёт оборот заново по нотам фразы.

Относительная нота: `chordIndex` — индекс участка, `degree` 1..13 относительно
мажорной интервальной основы корня реального аккорда, `chromaticOffset` -2..2.
Например, 3/-1 — малая терция, 7/-1 — малая септима, 13/-1 — b13. Октавный
регистр здесь не задаётся. Исходные ноты/ритм остаются неизменными; pitch-class
проекция в результате служит проверке, не является MIDI или готовым размещением.

Source rule выбирается только из каталога этого участка, с сохранением provenance
эквивалентных трактовок. Если совпадают разные корни/наборы, требуется уточнение;
если правило исчезло, применение несовместимо; неизвестная версия требует
повторной проверки. Метка tension не разрешает отсутствующий source rule.

## Роли нот и проходящие звуки

- chordAnchor — написанный тон аккорда/явный slash bass;
- guideTone — имеющаяся направляющая из рассчитанного каталога;
- sourceTone — тон выбранного совместимого источника, без заявления устойчивости;
- characteristicTone — характерная нота выбранного применения;
- resolutionTarget или прежний `target=true` — реальный тон аккорда указанного
  участка. Это проверка принадлежности цели, не обещание равной устойчивости
  всех extensions. Окончание фразы не объявляется целью автоматически;
- passingApproach — только с полной описанной группой подхода/enclosure;
- outsideTone — недостаточно данных до отдельной outside/side-slip policy.

`PhraseApproach` ссылается на существующий `HarmonicConcept` подхода/enclosure.
Проверяются полный порядок +1/-1/0 либо -1/0, роли, цель, последовательные индексы
нот и отсутствие перекрытия подготовки/разрешения. При цели next chord приземление
происходит на начале следующего участка и на фактическом следующем аккорде,
совпадающем с целью готового концепта. При current chord — внутри текущего.

Одна пометка passing или T3 не разрешает произвольную хроматику. При этом
одобренный хроматический подход может содержать ноту вне основной гаммы: проверка
не сводится к принадлежности всех нот одной гамме. Расширенные диатонические
passing/tie/outside модели добавляются позже через явные условия, не догадки.

## Фактическая и предполагаемая цель

Результат отдельно сохраняет реальный текущий аккорд, actual next chord,
существующий ResolutionTarget и DominantDestination snapshot с подтверждённостью.

В Corcovado A7b13 может использовать D harmonic minor по предполагаемой Dm цели,
а реальный следующий аккорд оставаться D7. Нота F# в этом D7 проверяется по
фактической гармонии; F не допускается как его написанная терция. Предполагаемый
Dm не вставляется в timeline, не подменяет D7 и не подтверждается одним tension.

## Результат и ограничения

`harmonic`: compatible / incompatible / insufficientContext; diagnostics имеют
код, участок, ноту и пояснение. Несовместимость и отсутствие данных различаются.

Только после compatible вычисляется `tension`: any / matches / unclassified /
differentLevel; до этого он notEvaluated. `eligible()` возвращает true лишь для
гармонически совместимого кандидата в «Все» или с явно совпавшим уровнем. При
неоценённом tension фраза доступна в «Все», но не считается автоматически T1.

Проверяются конечные времена, положительные длительности, порядок, границы и
наличие участков. Нота, удерживаемая через смену гармонии, требует явного split/tie
контекста; 0.4e возвращает insufficientContext вместо молчаливого разрешения.
Нет аудио-thread API, файловых операций, генерации, ранжирования или мутации фразы.
