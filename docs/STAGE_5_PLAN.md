# Stage 5 — Phrase / Idea Library

Начало этапа: 2026-10-01, по указанию Влада после принятого Stage 4.
База — stable 0.5, main `2f3cf3a`, Windows run `36867908179`, 27/27 CTest.
0.5a реализуется отдельным PR: [контракт](STAGE_5_0.5a_LIBRARY_CONTRACT.md).
Windows CI и Studio Pro regression acceptance ещё ожидаются; 0.5b не начат.

Рабочая линия: **0.5a → 0.5g**. Итог Stage 5: **stable 0.6**.
Каждая буква — отдельная сборка, regression и доступный Studio Pro live gate;
новые внутренние контракты до появления UI проверяются автоматически.

## Что уже готово и используется повторно

`Phrase` хранит относительные ноты, beats/длительности, роли, target flags,
гармонический pattern, требования к slots/source rules и approach/enclosure.
`assessPhrase` проверяет гармонию перед tension; `PhraseTensionProfile` и
`TensionCurve` описывают разные данные и не меняют ноты при смене запроса.

Готовый каталог источников, объяснения, confidence/provenance, фильтр и ручные
метки материалов остаются источником гармонического evidence. Библиотека не
распознаёт аккорды заново и не назначает неизвестным фразам T1.

Полноценная транспозиция — Stage 6; музыкальное размещение и Song persistence —
Stage 7; нотный/TAB редактор — Stage 8; преобразование фразы — Stage 9.
Модель нот сейчас проверяет pitch classes. Перед готовыми библиотечными фразами
нужно явно сохранять октавный регистр/контур, не выдумывая MIDI-высоту по pitch class.
Эта совместимость с будущей транспозицией входит в контракт 0.5a.

## Минимальный ввод своей Idea

Перед 0.5d нужно выбрать с Владом UX, как требует действующий roadmap.
Исходный вариант для обсуждения: название, текстовая идея/concept и необязательные
заметки о ритме/гармонии; незаполненные данные остаются неизвестными.
Простой ввод последовательности ступеней/длительностей можно добавить при согласовании.
Импорт MIDI/запись гитары/полный нотный редактор не включаются скрыто в эту задачу.
Это решение не блокирует модель, API и сохранение 0.5a–0.5c.

## Поиск и назначения

Частичная Idea хранится и доступна в обычном просмотре, но не превращается в
подтверждённую готовую фразу. Поиск должен различать compatible / incompatible /
insufficientContext и причины. Уровень из общего профиля способов обыгрывания
не переносится автоматически в описательный tension фразы.

Изменение желаемого уровня/кривой меняет подбор, не сохранённый материал.
Rank выбирает только среди допустимых кандидатов, не прячет неоднозначность и
не делает неподходящий источник допустимым. Цель actual next chord и предполагаемая
цель оборота остаются раздельными. Неизвестная source version требует revalidation.

## Сохранение и независимость

Library item — переносимый словарь. Common originals не редактируются напрямую;
личная копия/вариант имеет самостоятельную identity и сохраняет происхождение.
Изменение или удаление источника не должно переписывать уже сделанные копии.

0.5c реализует user library persistence, не Song workspace. Формат/schema и
путь/правила конфликтов определяются перед реализацией persistence, с проверкой
нескольких экземпляров и процессов. Общие ручные tensions Stage 4 остаются отдельным
профилем. Они не хранятся заново внутри каждой library record.

0.5g готовит контракт независимого song instance с локальным snapshot материала,
source ID/version и явным musical anchor/range. Реальное следование за структурными
правками DAW, Save As/project identity и backend Song workspace подтверждаются
перед Stage 7, а не обещаются на основании библиотечного контракта.

## Первый общий набор

Объём MVP определяется перед 0.5f после проверки поиска и UX. Основа — собственные
либо явно разрешённые примеры; книги остаются учебными источниками и не превращаются
автоматически в распространяемый набор транскрипций. Source/license metadata
каждого поставляемого примера проверяется отдельно. Начальные уровни задаёт Влад,
можно оставить неоценённые примеры; автоматическое заполнение всех уровней не gate.

## Критерий завершения

- Свои Ideas/Phrases и копии общего материала сохраняются и восстанавливаются.
- Оригиналы, копии, варианты и будущие размещения независимы; lineage сохранён.
- Относительные ноты, регистр, ритм, sources/roles/targets не теряются.
- Поиск объясняет гармоническую пригодность и tension, не меняет пользовательские ноты.
- У поставляемых примеров есть проверенные метаданные и объяснение.
- Contract library → Stage 6/7 определён без преждевременной реализации этих этапов.
- 0.5a–0.5g приняты, Windows/regression/live gates пройдены; отдельная stable 0.6
  собрана, Issue #6 закрыт только после этого.
